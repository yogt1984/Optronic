# SPEC-09 Test Plan

## 1. Levels
| Level | Where | What | Tooling |
|---|---|---|---|
| L1 unit | host | framework components in isolation, FakeMmio, fake clock | GoogleTest, ASan/UBSan/TSan |
| L2 host integration | host (Docker) | full service with `videotestsrc`, fake HAL, local mosquitto, `nodectl` | ctest + python harness |
| L3 target | PetaLinux QEMU (`zcu104`/`zcu102` machine from the SDK image) on every push; real board nightly | GoogleTest binaries cross-built with the PetaLinux SDK run on target: HAL/UIO mapping + irq plumbing against a `uio_pdrv_genirq` node, lifecycle, config, ipc, logger; pipeline PLAYING with `videotestsrc`+software encoder; ICD answers | `ctest --preset arm64-qemu`, ssh runner |
| L4 HIL | customer lab only | real detector, PL block, VCU, thermal | out of scope — documented why |

Why L4 cannot be replaced: detector timing/NUC drift, dma-buf cache coherency on HP vs HPC ports, VCU rate control, thermal behaviour. L1–L3 exist to make L4 time cheap. L3 in QEMU validates the **toolchain/sysroot/ABI and the Linux plumbing** (UIO, sockets, threads, GStreamer software path) — not PL or VCU behaviour.
